## 0. 이 문서가 답하는 질문

"프로토타입을 만든다"는 말이 명세 안에서 세 가지를 가리킨다. 지금 만드는 건 **M1**이다.

| | 무엇 | 버리는가 | 상태 |
|---|---|---|---|
| 클릭 프로토타입 | 아티팩트 `시관 프로토타입` | 버림 | 이미 있음 |
| **M1 웹 프로토타입** | **모노레포 + React/Vite + 로컬 저장** | **그대로 본 개발로 이어짐** | **← 지금** |
| 기술 검증 | 타임라인 엔진만 떼어낸 스파이크 | 버림 | M1 안에 흡수됨 |

M1의 목적은 "쓸 만한 웹앱"이 아니라 **간트/드래그드롭이 쓸만한지를 2주 안에 아는 것**이다. 명세 14장이 백엔드를 M2로 미룬 이유가 이거다. 그러니 M1에서 로그인·서버·동기화를 건드리면 목적을 배신하는 것이다.

## 1. 지금 당장 (30분)

```bash
# Mac 터미널에서
cd ~/Documents/sigwan

corepack enable && corepack prepare pnpm@latest --activate
nvm install 24 && nvm use          # .nvmrc가 24로 박혀 있다
pnpm install

pnpm test                          # ← 여기서 멈추면 안 된다
pnpm dev                           # http://localhost:5173
```

`pnpm test`가 통과하면 **명세 4장 검산표 다섯 줄이 코드로 재현된 것**이다. 이게 M0의 실질적인 완료 조건이다 — 명세에 적힌 숫자와 코드가 일치한다는 증거가 리포 안에 있다는 뜻이니까.

> 검산표의 "포폴 리뉴얼"은 명세가 마감을 `10-15`로만 적었다. 표의 slack 1012h를 재현하는 시각은 **10-15 14:00**이고, 테스트에 그렇게 박아뒀다. 회의 때 이 시각을 확정하고 명세를 고칠 것.

이후 git:

```bash
git init && git add -A
git commit -m "M0: 모노레포 + core 타입·점수·타임라인 좌표계 + 목 데이터"
gh repo create sigwan --private --source=. --push
```

## 5. 막힐 만한 곳 다섯 군데

**1. 드래그가 끊긴다**
`onPointerMove`에서 setState를 하면 프레임마다 리렌더가 돈다. 현재 코드는 DOM의 `transform`/`height`만 직접 바꾸고, **포인터를 뗄 때 한 번만** 저장한다. 이 구조를 깨지 마라. 모바일(M3)에서는 이게 reanimated의 UI 스레드로 옮겨간다.

**2. 스냅 값이 DB에 들어간다**
스냅은 화면에서만 일어난다(3.2). `snap()`은 렌더·드래그 계산에만 쓰고, 저장되는 건 항상 정확한 타임스탬프다. 여기가 섞이면 M2 동기화에서 LWW 충돌 해결이 이상해진다.

**3. 타임존**
전부 UTC `timestamptz`로 저장하고 표시할 때만 변환한다. **단 `day_of`는 로컬 날짜 문자열**이다 — UTC로 저장하면 자정 근처에서 오늘 할 일이 어제로 밀린다. `score.ts`의 `effectiveDueAt()`이 `day_of`를 로컬 Date로 직접 조립하는 게 그 이유다. 테스트는 `TZ=Asia/Seoul`로 고정돼 있다.

**4. 겹침 레인이 들쭉날쭉하다**
`layoutBlocks`는 시작 시각 순 그리디다. 끝난 레인을 재사용하므로 최소 레인 수가 나오지만, **같은 블록이 줌마다 다른 레인에 갈 수 있다.** 사용자가 헷갈리면 레인을 Task ID 해시로 고정하는 쪽으로 바꿔야 하는데, 그러면 레인 수가 늘어난다. 트레이드오프고, M1에서 눈으로 보고 정해라.

**5. 점수를 캐시하고 싶어진다**
`tasks.score` 컬럼이 스키마에 있다(5장). 하지만 `slack`이 `now`에 의존하므로 **캐시는 시간이 지나면 틀린다.** M1에서는 캐시하지 마라. 서버 정렬 인덱스가 필요해지는 M2에서, "몇 분 단위로 재계산" 같은 정책을 같이 정하고 넣는 게 맞다.

## 6. 아직 안 정해진 것 — 회의에 가져갈 것

명세 "다음 결정할 것" 중 M1 착수 전에 걸리는 순서대로:

1. **AI 기능 통합 방식 (A/B)** — 12장 화면 구성과 16.2 모듈 배정이 여기 걸려 있다. **M0에서 정해야 한다.** 나중이면 앱 셸을 다시 짠다
2. **패키지명·앱 이름** — 영구 불변(13.2). 오늘 정해도 되는 결정을 미룰 이유가 없다
3. **P1~P5 실명 배정** — 특히 모듈 ①(타임라인)을 누가 받는가. 명세가 "①은 혼자 두지 않는다"고 못 박아뒀다
4. **백엔드(8장)** — M2가 1주냐 5주냐. 다만 이건 **M1 끝날 때까지 미뤄도 된다.** Repository 인터페이스가 이미 그 결정을 격리하고 있다
5. **주 뷰 = 읽기 전용** 확정 → 명세 3.1·12장 수정
6. **포폴 리뉴얼 마감 시각** → 검산표 slack 1012h를 맞추는 값 확정

> 5·6은 내가 이번 주에 코드로 먼저 답을 냈으니, 회의에서는 확인만 받으면 된다.
